# GitHub Search Automation Project

## Описание проекта
Данный проект представляет собой выполнение практического тестового задания для оценки навыков тест-дизайна, архитектурного подхода к автоматизации тестирования (POM) и качества написания автотестов.

Проект автоматизирует тестовый сценарий глобального поиска GitHub:
1. Открытие главной страницы GitHub.
2. Ввод ключевого слова **"copilot"** в глобальный поиск и инициация поиска.
3. Поиск репозитория **CopilotKit** в результатах выдачи и переход на его страницу.
4. Проверка корректности открытия репозитория и наличия ключевого слова **"CopilotKit"** в содержимом файла `README.md`.


## Технологический стек
* **Язык**: Python (версия >= 3.12)
* **Фреймворк автоматизации**: Playwright (версия 1.55.0)
* **Тестовый фреймворк**: PyTest (версия 8.4.1)
* **Управление зависимостями**: pip & `requirements.txt`
* **Шаблон проектирования**: Page Object Model (POM)
* **Браузер**: Google Chrome (запуск через Chromium Engine с явным каналом `chrome`)

## Инструкция по развертыванию проекта

### 1. Системные требования
Убедитесь, что на вашем компьютере установлен Python версии 3.12 или выше. Проверить версию можно командой:
```bash
python3 --version
```

### 2. Клонирование и создание виртуального окружения
Перейдите в директорию проекта и создайте изолированное виртуальное окружение:
```bash
# Создание виртуального окружения
python3 -m venv .venv

# Активация виртуального окружения (macOS/Linux)
source .venv/bin/activate

# Активация виртуального окружения (Windows PowerShell)
# .venv\Scripts\Activate.ps1
```

### 3. Установка зависимостей
Установите необходимые библиотеки (PyTest, Playwright) и системные бинарные файлы браузеров:
```bash
# Обновление pip и установка пакетов из requirements.txt
pip install --upgrade pip
pip install -r requirements.txt

# Установка браузерных ядер Playwright
playwright install chromium
```


## Инструкция по запуску тестов

### Запуск через Терминал
Все команды запуска должны выполняться при **активированном** виртуальном окружении `.venv`.

* **Стандартный запуск в headless-режиме (без отображения окна браузера):**
  ```bash
  pytest
  ```

* **Запуск с отображением интерфейса браузера Google Chrome (headed режим):**
  ```bash
  pytest --headed
  ```

* **Запуск с замедлением действий на 500мс:**
  ```bash
  pytest --headed --slowmo 500
  ```

* **Запуск с явным указанием канала Google Chrome:**
  ```bash
  pytest --browser-channel chrome
  ```

### Запуск и отладка из PyCharm IDE
1. Откройте проект `testing_case` в **PyCharm**.
2. Перейдите в настройки: `Settings` (или `Preferences` на macOS) -> `Project: testing_case` -> `Python Interpreter`.
3. Нажмите `Add Interpreter` -> `Add Local Interpreter...` -> Выберите `Existing` и укажите путь к интерпретатору виртуального окружения: `/Users/<имя_пользователя>/Desktop/testing_case/.venv/bin/python`. Нажмите Apply.
4. Откройте файл `tests/test_github_search.py`.
5. Слева от названия функции `test_github_search_and_navigate_to_copilotkit` нажмите зеленую кнопку запуска (треугольник) и выберите **Run 'pytest for test_github...'**.
6. **Для отладки (Debugging)**: Поставьте breakpoint (красную точку) в коде автотеста или любого Page Object файла, кликните по зеленому треугольнику правой кнопкой мыши и выберите **Debug 'pytest for test_github...'**.


## Архитектурные особенности и паттерны

### 1. Page Object Model (POM)
Вся логика взаимодействия с UI вынесена в отдельные классы страниц (`pages/`):
* `BasePage` — инкапсулирует базовые вызовы Playwright (wait, click, fill, press). Предотвращает дублирование кода и повышает читаемость.
* `MainPage`, `SearchResultsPage`, `RepositoryPage` — представляют конкретные страницы сценария, объявляя только необходимые для теста локаторы и высокоуровневые бизнес-действия.

### 2. Надежные и гибкие XPath-локаторы
Для удовлетворения строгих требований к надежности и гибкости локаторов, в проекте используются передовые возможности XPath:
* **Логические операторы (`or`, `and`, `not`)**: Используются для поиска по альтернативным атрибутам.
* **Поиск по частичному совпадению классов**: Конструкции `contains(@class, 'search-result')` защищают локатор от динамических суффиксов в именах CSS-классов (актуально для CSS-модулей React/Next.js на GitHub).
* **Спецификация осей (`ancestor`)**: Позволяет локализовать элемент в рамках конкретного логического блока, отсекая ложные совпадения.
* **Исключение дубликатов в строгом режиме (Strict Mode)**:
  В `SearchResultsPage.py` локатор `COPILOTKIT_REPO_LINK_XPATH` спроектирован так, чтобы предотвратить ошибку *strict mode violation* (когда под один селектор подходят основной репозиторий и его дочерние элементы, например вкладка Stars/Forks):
  ```xpath
  //a[(@href='/CopilotKit/CopilotKit' or (contains(@href, '/CopilotKit/CopilotKit') and not(contains(@href, '/stargazers')) and not(contains(@href, '/forks')))) and (ancestor::div[contains(@class, 'search-result')] or @data-component='Link')]
  ```
  Этот локатор находит ссылку на проект на любом уровне вложенности результатов поиска, полностью исключая служебные ссылки stargazers или forks.
